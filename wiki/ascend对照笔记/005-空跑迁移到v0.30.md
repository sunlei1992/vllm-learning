## 2. 第 1 步：vLLM 0.30.0 的空跑移植

### 2.1 补丁移植量：5 个 hunk + 1 处 API 适配

```text
vllm/config/cache.py                           1 hunk   （hash 排除列表加 simulate_forward）
vllm/model_executor/model_loader/base_loader.py 1 hunk  （meta device 跳过权重后处理）
vllm/engine/arg_utils.py                       2 hunks  （配置块 + trace replay 默认值）
vllm/v1/worker/gpu/model_runner.py             1 hunk   → 不适用（0.30 没有 aux_output）
```

手工修完后编译通过。

**额外一处 API 差异**（补丁本身没覆盖）：

```python
# vllm/v1/worker/simulated/model_runner.py
self.prepare_inputs(..., num_active_loras=0)
# 0.30 的签名没有这个参数 → TypeError
```

删掉该参数即可。

### 2.2 构建

复用 `sim-built` 镜像里已编译好的 ACL，oneDNN 重新编（约 7 分钟），
vLLM 装进独立 venv（`--system-site-packages`，复用系统 torch）：

```bash
python -m venv --system-site-packages --without-pip /opt/v030
export VLLM_TARGET_DEVICE=cpu ACL_ROOT_DIR=/work-acl \
       FETCHCONTENT_SOURCE_DIR_ONEDNN=/work-onednn \
       SETUPTOOLS_SCM_PRETEND_VERSION=0.30.0 MAX_JOBS=2
uv pip install --python /opt/v030/bin/python --no-build-isolation --no-deps -e .
# 结果：vllm==0.30.0+cpu，7m33s
```

镜像：

| 镜像 | 内容 |
| :-- | :-- |
| `sim030:build` | vLLM 0.30.0 + 编译产物 |
| `sim030:dry-run` | + triton/torchvision/torchaudio/torchcodec `+cpu` + `num_active_loras` 修复 |

跑法：`./assets/simulate-forward/run_smoke_030.sh`

## 3. 第 2 步：vllm-ascend 0.30 的空跑

### 3.1 版本

```text
tmp/va030   branch sim-0.30 ← origin/releases/v0.30.0（HEAD f03228c14）
            pin: ced6857af = vLLM v0.30.0  ← 与 sim030 镜像一致
```

### 3.2 复用 004 的全部手段

| 手段 | 0.30 是否需要改 |
| :-- | :-- |
| 6 个 stub（torch_npu / torch.npu / `_build_info` / triton cann / HCCL / `torch_npu._C`） | 不用改 |
| `register()` 无 NPU 返回 None | 不用改 |
| 伪造 `dist-info/entry_points.txt` | 不用改 |

### 3.3 新增一个问题：VA 覆盖了 MRV2 判定

VA 的 `patch_use_v2_model_runner.py` 直接替换了上游的 property：

```python
def _patched_use_v2_model_runner(self) -> bool:
    use_v2 = envs.VLLM_USE_V2_MODEL_RUNNER
    if use_v2 is not None:
        return use_v2
    return False
```

它**丢掉了**上游"`simulate_forward` 隐含 MRV2"的逻辑，于是：

```text
ValueError: trace replay requires Model Runner V2
```

**解法**：显式设置

```bash
export VLLM_USE_V2_MODEL_RUNNER=1
```

### 3.4 运行

```bash
./assets/simulate-forward/va/run_va_dry_run_030.sh
```

结果：4 个 general plugin 全 OK，补丁生效，空跑输出正确。

## 5. 代价与建议

| 项 | 成本 |
| :-- | :-- |
| 补丁移植（5 hunk + 1 API） | ~2 小时 |
| 重建镜像（oneDNN + vLLM） | ~10 分钟 |
| VA 0.30 接入（含 MRV2 坑） | ~1 小时 |
| 总计 | **半天左右** |

建议：

- **日常实验继续用 main 镜像**（`sim-built`），补丁冲突最少
- **需要和 VA 0.30 对齐时**用 `sim030:*`（比如验证 VA 0.30 的补丁行为）
- 0.30 的价值主要是"离 release 更近"，不是"空跑能力更强"

> 这套 0.30 的改动同样只用于本地实验，不提交上游。
