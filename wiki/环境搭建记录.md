## 2. 搭建步骤（完整命令）

### 2.1 安装 uv（走 Homebrew）

```bash
brew install uv
```

> **为什么不用官方脚本** `curl -LsSf https://astral.sh/uv/install.sh | sh`：
> 该脚本从 GitHub Releases 下载，本机 github.com 直连不通，下载超时；brew 走自己的 CDN，秒装。

### 2.2 安装编译工具链

```bash
brew install cmake ninja
```

> vLLM 源码编译依赖 cmake + ninja（纯 Python 改动不需要，但首次必须）。

### 2.3 安装 Python 3.12（uv 管理）

```bash
uv python install 3.12
```

> vLLM 0.28.0 要求 Python `>=3.10,<3.15`，系统自带的 3.9.6 不满足。
> 装完路径：`~/.local/share/uv/python/cpython-3.12.../bin/python3.12`

### 2.4 获取 vLLM v0.28.0 源码

```bash
# 方式一（本机实测可用）：GitHub API 下载 tarball（走 codeload 通道，快）
curl -sL -o /tmp/vllm-v0.28.0.tar.gz \
  "https://api.github.com/repos/vllm-project/vllm/tarball/v0.28.0"
# 39.8MB，本机实测 11 秒

# 方式二：git clone（需要代理，见 git使用指南.md）
git clone https://gh-proxy.com/https://github.com/vllm-project/vllm.git vllm-src
```

> 注意：tarball 没有 `.git`，后续要么补 git 历史（我们做了，见 git使用指南.md），
> 要么编译时用 `VLLM_VERSION_OVERRIDE` 兜底版本号。

### 2.5 创建虚拟环境 + 安装依赖

```bash
cd ~/code/dsh/vllm
uv venv --python 3.12
uv pip install --python .venv/bin/python -r vllm-src/requirements/cpu.txt \
  --index-strategy unsafe-best-match
```

> 实测装了 144 个包，含 torch 2.13.0、transformers 5.16.1。
> `--index-strategy unsafe-best-match`：允许跨多个包索引（PyTorch 源 + PyPI）解析依赖，
> 不加会报 `typing-extensions` 版本冲突。名字里的 "unsafe" 指解析策略，不是安全问题。

### 2.6 源码编译安装（关键步骤，约 10-30 分钟）

```bash
uv pip install --python .venv/bin/python -e vllm-src
```

macOS 上 `VLLM_TARGET_DEVICE` 自动设为 `cpu`，无需手动指定。

**首次编译会踩的坑**：`setuptools-scm was unable to detect version`。
原因：源码没有 `.git`，版本检测失败。解决：

```bash
VLLM_VERSION_OVERRIDE=0.28.0 uv pip install --python .venv/bin/python -e vllm-src
```

> vLLM 官方支持 `VLLM_VERSION_OVERRIDE`（setup.py 里读取，会写入 `vllm/_version.py`）。
> 后来补了 git 历史之后，这个变量就不需要了（setuptools-scm 能从 git tag 推断）。
> 编译产物：`vllm-src/vllm/_C.abi3.so`、`spinloop.abi3.so`、`fs_io_C.abi3.so`。

### 2.7 验证

```bash
source env.sh
.venv/bin/python -c "import vllm; print(vllm.__version__)"   # → 0.28.0
.venv/bin/python demo_inference.py                            # → 跑通推理
```

## 3. 运行时环境变量（env.sh 内容说明）

```bash
export PATH="/opt/homebrew/bin:$PATH"     # brew 的 uv/cmake/ninja
export UV_CACHE_DIR="$PWD/.uv-cache"      # uv 缓存放工作区（默认 ~/.cache/uv）
export HF_HOME="$PWD/.hf-cache"           # HF 模型缓存放工作区
export VLLM_CACHE_ROOT="$PWD/.vllm-cache" # vLLM 缓存放工作区
```

**为什么缓存要放工作区**：这些缓存默认写 `~/.cache/...`，在受限环境下会报
`Operation not permitted`；放工作区后无权限问题，删目录即清缓存。
**注意**：不要定义 `VLLM_` 前缀的自定义变量，vLLM 启动会警告
`Unknown vLLM environment variable`。

## 4. 运行/调参要点

### 4.1 内存参数（Mac 上最容易踩的坑）

CPU 后端下，`--gpu-memory-utilization`（名字带 GPU，实际管 CPU 内存）控制保留内存比例。
启动校验：**当前可用内存 ≥ 24GB × 比例**。

| 比例 | 需要 | 实测可用 | 结果 |
|---|---|---|---|
| 0.92（默认） | 22.1 GB | 8~15 GB | ❌ 必挂 |
| 0.5 | 12 GB | 波动 | ❌ 有时挂 |
| 0.35 | 8.4 GB | 波动 | ❌ 有时挂 |
| **0.25** | 6 GB | 波动 | ✅ 稳 |

报错特征：`Available memory on node 0 (X/24.0 GiB) ... less than desired` → 继续调低。
125M 小模型实际只要 ~1GB，比例低完全够用。

### 4.2 关键日志解读

- `Model Runner V2 requires Triton; using the V1 model runner instead`
  —— Mac 无 Triton，自动回退 V1 model runner（vLLM 同时维护 V1/V2 两套）
- `Chunked prefill is enabled with max_num_batched_tokens=4096`
  —— 连续批处理 + chunked prefill 是 vLLM 核心机制
- `device_config=cpu` —— 确认走 CPU 后端

### 4.3 多进程与调试模式

V1 引擎默认多进程：主进程 → EngineCore → WorkerProc。
**调试时设 `VLLM_ENABLE_V1_MULTIPROCESSING=0`** → 引擎进程内运行（InprocClient），
单个 VSCode 调试器可跟到底（.vscode/launch.json 已配好）。
注意：`vllm serve`（asyncio 模式）不支持进程内运行（0.28.0 会报 NotImplementedError）。

### 4.4 开启多 rank（本地模拟多节点 CPU）✅ 实测 2026-09-03

Mac 是 **UMA 架构（无 NUMA）**，CPU 后端的线程绑定逻辑要求"每个 worker 一个 NUMA 节点"，
直接设 `tensor_parallel_size=2` 会报：

```
Not enough allowed NUMA nodes to bind threads of 2 local CPUWorkers.
Allowed NUMA nodes are [0].
```

**解法**：加环境变量 **`VLLM_CPU_SIM_MULTI_NUMA=1`**（`vllm/utils/ompmultiprocessing.py:36` 读取），
在单 NUMA 机器上模拟多节点，手动给每个 rank 分核。官方为 CI 测试 CPU 多 worker 设计。

```bash
# 实测跑通：2 个真实 worker 进程 + gloo 通信 + 权重按 TP 切分
VLLM_CPU_SIM_MULTI_NUMA=1 .venv/bin/python -c "
from vllm import LLM
llm = LLM(model='facebook/opt-125m', load_format='dummy', enforce_eager=True,
          max_model_len=64, dtype='float16', gpu_memory_utilization=0.25,
          tensor_parallel_size=2)
out = llm.generate(['multi rank test'])
print(out[0].outputs[0].text)
"
```

预期日志（真实多 rank 证据）：
```
world_size=2 rank=0 local_rank=0 ... backend=gloo      # worker 1
world_size=2 rank=1 local_rank=1 ... backend=gloo      # worker 2
local_rank=0, core ids=[0,1,2]                         # 各分 3 个核
local_rank=1, core ids=[4,5,6]
```

**本地多 rank 能做什么 / 不能做什么**：

| 并行维度 | 能否 | 说明 |
|---|---|---|
| TP（张量并行） | ✅ 实测 | 权重切分 + gloo 跨进程通信 |
| DP（数据并行） | ✅ 应可 | 同一机制 |
| **PCP**（prefill 上下文并行） | ❌ | **V2-runner-only**（`config/vllm.py:620`），CPU 走 V1 runner——比 NUMA 更深的墙 |
| DCP（decode 上下文并行） | ❌ 大概率 | CPU 注意力后端支持有限 |

> 想体验 PCP 的切分/还原逻辑：用 `tests/` 里的 PCPManager 单测（不跑引擎），或需要 NPU/多 GPU 环境。

## 5. 测试脚本用法（demo_inference.py）

```bash
source env.sh
.venv/bin/python demo_inference.py                          # dummy 权重，验证链路
.venv/bin/python demo_inference.py --prompt "你好" --mem 0.2
.venv/bin/python demo_inference.py --model Qwen/Qwen2.5-0.5B-Instruct --load-format auto
```

- 默认 `--load-format dummy`：随机权重，不下载模型，输出乱码是正常的（验证链路用）
- `--load-format auto`：下载真实权重到 `.hf-cache/`（HF 慢可设 `HF_ENDPOINT=https://hf-mirror.com`）

## 6. 常见问题排查（按概率排序）

| 现象 | 原因 | 解决 |
|---|---|---|
| `Available memory ... less than desired` | 空闲内存不足 | `--mem 0.2~0.25` |
| `setuptools-scm was unable to detect version` | 无 `.git` | `VLLM_VERSION_OVERRIDE=0.28.0` |
| 缓存目录 `Operation not permitted` | 默认缓存在工作区外 | `source env.sh` |
| `Unknown vLLM environment variable` | 自定义了 `VLLM_*` 变量 | 删掉该变量 |
| 编译报 `'map' file not found` | Xcode CLT 异常 | 重装 `xcode-select --install` |
| 断点打不中引擎内部 | 多进程模式 | 设 `VLLM_ENABLE_V1_MULTIPROCESSING=0` |
| **HF 下载失败**（`Distant resource does not seem to be on huggingface.co`） | huggingface.co 直连不通；huggingface_hub 1.28 对 hf-mirror 的 HEAD 校验失败（mirror 返回 307 重定向） | 用 `./dl_model.sh <模型名>` 从镜像 curl 下载 config+tokenizer 到 `models/`，然后 `--model models/xxx` 走本地路径（dummy 模式不需要权重） |
| 长上下文模型报 KV cache 不足 | config 的 max_seq_len 太大（如 Qwen3 是 40960） | 加 `--max-model-len 4096` |

## 7. 一句话总结（防忘）

> **Mac 上没有 vLLM 预编译包 → 必须源码编译（CPU 后端）→ 编译要 cmake/ninja + 版本兜底变量 →
> 跑起来要调低内存比例 → 调试要关多进程。环境 = `source env.sh` + `.venv/bin/python`。**
