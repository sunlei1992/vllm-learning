# 004 CLI 与配置体系

> 一句话：**三种驱动方式**（命令行参数 / 自定义 Python 配置文件 / 全局常量文件），配置用 mmengine 的 `read_base()` 组织。搞清优先级和"谁是唯一标识"就不会乱。
> 版本基线：`v3.1-20261013-master`。

## 1. 三种驱动方式

| 方式 | 写法 | 适用 |
|---|---|---|
| ① CLI 参数 | `ais_bench --models A --datasets X` | 快速试、笛卡尔积组合 |
| ② 自定义配置文件（推荐） | `ais_bench my_config.py` | 复杂场景、复用、需要 Python 逻辑 |
| ③ 全局常量文件 | 改 `ais_bench/benchmark/global_consts.py` | 不区分任务的全局行为（超时、日志级别…） |

官方态度明确：**推荐 ②**。理由——改一个文件集中管理、一次编写多次复用、支持全部 Python 语法；而 ① 只支持笛卡尔积组合。

### 互斥关系（重要）

【文档】指定了自定义配置文件路径后，`--models` / `--datasets` / `--summarizer` **全部失效**。

```bash
ais_bench my_config.py --models xxx        # --models 被忽略，不报错，容易懵
```

但公共参数（`--reuse` / `--mode` / `--max-num-workers` / `--num-prompts` / `--merge-ds` / `--debug` …）仍然可以在命令行追加 —— 这是 ② 的常规用法。

## 2. 公共参数（全模式通用）

【文档】

| 参数 | 说明 | 备注 |
|---|---|---|
| `config` | 自定义配置文件路径（位置参数，无 `--`） | 与 `--models` 互斥 |
| `--models` | 模型任务名（`configs/models` 下的文件名） | 可传多个 |
| `--datasets` | 数据集任务名（`configs/datasets` 下） | 可传多个 |
| `--summarizer` | 结果汇总任务名 | 精度默认 `example`，性能默认 `default_perf` |
| `--mode` / `-m` | `all/infer/eval/viz/perf/perf_viz/agent/agent_viz` | 默认 `all` |
| `--reuse` / `-r` | 复用指定时间戳目录，继续执行并覆盖结果 | 不加则自动取 `--work-dir` 下最新 |
| `--work-dir` / `-w` | 结果根目录，默认 `outputs/default` | |
| `--config-dir` | 配置文件根目录，默认 `ais_bench/benchmark/configs` | |
| `--debug` | 所有日志打屏（不落盘），**强制 `--max-num-workers=1`、单核** | 调试用，压测别开 |
| `--dry-run` | 只打屏不实际跑 | 验证配置 |
| `--merge-ds` | 同类数据集合并推理 | 见 003 §2.5 |
| `--num-prompts` | 取前 N 条 | 按顺序，不支持随机 |
| `--max-num-workers` | 并行子任务数，`[1, CPU 核数]`，默认 1 | `--debug` 下无效 |
| `--num-warmups` | 预热次数，默认 1；设 0 不预热 | warmup 全失败则不跑正式任务 |
| `--response-anomaly` | 开推理响应异常检测 | 需服务返回 token id + top-k logprobs；不支持 perf/agent |
| `--response-anomaly-payload-retention` | `all` / `anomalies` / `none`，默认 `anomalies` | 检测后 payload 保留策略 |
| `--max-workers-per-gpu` | 预留，暂不支持 | |

## 3. API 模型通用覆盖参数

【文档】2026-08 新增，专治"改一行配置要开编辑器"。只对 `attr="service"` 生效；`attr="local"` 会被忽略并打 warning。

| 参数 | 覆盖字段 |
|---|---|
| `--path` | `path`（tokenizer / 词表路径） |
| `--model-name` | `model`（VLLM）或 `model_name`（Triton）；MindIE/TGI 不接收则 warning 跳过 |
| `--request-rate` | `request_rate` |
| `--retry` | `retry` |
| `--api-key` | `api_key` |
| `--host-ip` | `host_ip` |
| `--host-port` | `host_port` |
| `--url` | `url`（配了会忽略 host_ip/host_port） |
| `--max-out-len` | `max_out_len` |
| `--batch-size` | `batch_size` |
| `--trust-remote-code` / `--no-trust-remote-code` | `trust_remote_code` |
| `--generation-kwargs` | `generation_kwargs`，JSON 字符串，**整体替换**不是合并 |

**覆盖规则**（容易踩）：

1. 只覆盖配置里**已存在**的字段，不新增（保证向后兼容）。
2. 未显式指定的参数不生效（默认 `None`），保持配置文件原值。
3. 同一命令里多个服务化模型任务**都**会被覆盖。
4. `--generation-kwargs '{"temperature":0.5}'` 会把原来的 `ignore_eos` 一起冲掉 —— 用之前先看配置文件里那份 dict。

## 4. 精度 / 性能 / Agent 专属参数

| 类 | 参数 | 说明 |
|---|---|---|
| 精度 | `--dump-eval-details` | dump 评估过程细节 |
| 精度 | `--dump-extract-rate` | dump 答案抽取速率 |
| 性能 | `--pressure` | 开压测模式（仅 `perf`） |
| 性能 | `--pressure-time` | 压测秒数，`[1,86400]`，默认 15 |
| 性能 | `--spec-decode` | 采投机推理指标（仅 `perf`） |
| Agent | `-a/--agent`、`--model`、`--api-base`、`-d`、`-p`、`-n`、`-k`、`-e`、`--n-tasks`、`--include-task-name`、`--monitor-port` … | 全套见 `cli_args` 页 Agent 章节 |

## 5. 自定义配置文件怎么组织

本质是一个 Python 脚本，用 mmengine 的 `read_base()` 把官方配置"导入"进来再覆盖：

```python
from mmengine.config import read_base

with read_base():
    from ais_bench.benchmark.configs.models.vllm_api.vllm_api_general_chat import models as vllm_chat
    from ais_bench.benchmark.configs.datasets.gsm8k.gsm8k_gen_4_shot_cot_str import gsm8k_datasets as datasets

models = vllm_chat

models[0]["host_ip"] = "127.0.0.1"
models[0]["host_port"] = 8000
models[0]["batch_size"] = 8
models[0]["generation_kwargs"] = dict(temperature=0.01, ignore_eos=False)

work_dir = "outputs/default/"
```

可定义的顶层变量：`models`、`datasets`、`summarizer`、`work_dir`、`model_dataset_combinations`、以及各类场景专用字段。

预置模板：
- `ais_bench/configs/model_api_test_zh_cn.py` —— 单文件管全部模型参数，最常用。
- `ais_bench/configs/accuracy_benchmark/*.py` —— 8 个场景样例（见 003 §2.9）。

## 6. 全局常量（`global_consts.py`）

【文档】不区分任务类型的全局行为，建议保持默认。

| 常量 | 默认 | 说明 |
|---|---|---|
| `WORKERS_NUM` | 0 | 请求发送进程数，0=按最大并发自动分配；`--debug` 下失效 |
| `MAX_CHUNK_SIZE` | 65535 字节 | 流式返回单 chunk 最大缓存，上限 16 MiB |
| `REQUEST_TIME_OUT` | `None` | 客户端等待超时，`None`=永久等待 |
| `LOG_LEVEL` | `INFO` | `DEBUG/INFO/WARNING/ERROR/CRITICAL` |
| `PRESSURE_TIME` | 15 | **将废弃**，用 `--pressure-time` |
| `CONNECTION_ADD_RATE` | — | **将废弃**，用模型配置里的 `request_rate` |

> 想让 PrefixCache 的运行细节落盘到 `.out`，得把 `LOG_LEVEL` 调成 `DEBUG`（默认 INFO 时 debug 日志不写文件）——见 006。

## 7. 三个"必须记住"的语义

1. **`abbr` 是唯一标识**。模型和数据集都靠 `abbr` 去重。用 `.copy()` 复制配置必须改 `abbr`，否则整个组合被静默跳过。
2. **`--reuse` 是"进目录继续跑"**，不是"读缓存"。它会**覆盖**该时间戳下的结果文件。配合 `--mode eval` 才是"只重评估"。
3. **`--debug` 会降并发**。`--max-num-workers` 被强制为 1 且单核发送请求——**性能数据在 `--debug` 下没有参考价值**。

## 8. 速查命令

```bash
# 查某个任务对应的配置文件绝对路径
ais_bench --models vllm_api_stream_chat --datasets gsm8k_gen --search

# 校验配置但不跑
ais_bench my_config.py --dry-run

# 只看推理，不看评估
ais_bench my_config.py -m infer

# 改完抽取函数只重评估
ais_bench my_config.py -m eval -r 20250628_151326

# 性能：指定 host/port/输出长度，不改配置文件
ais_bench --models vllm_api_stream_chat --datasets demo_gsm8k_gen_4_shot_cot_chat_prompt \
          -m perf --host-ip 10.0.0.5 --host-port 8000 --max-out-len 1024 \
          --generation-kwargs '{"temperature":0,"ignore_eos":true}'
```
