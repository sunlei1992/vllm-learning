# 008 坑与 FAQ

> 只记"踩了会浪费半天"的。分四类：环境/安装、命令与配置、数据与指标、PrefixCache。

## 1. 症状 → 原因 → 处理

| 症状 | 原因 | 处理 |
|---|---|---|
| `pip install` 报语法/依赖错 | Python 3.9 或 3.13 | 换 3.10/3.11/3.12 |
| `ais_bench -h` 找不到命令 | 装的是插件包或没装本体 | `pip3 install -e ./ --use-pep517`；插件入口是 `ais-bench-prefix-cache` |
| 指定了 `my_config.py`，`--models` 不生效 | 设计如此：config 与三者互斥 | 参数写进 config，或在命令行只用公共参数 |
| 4 个组合只跑了 2 个 | `abbr` 重复被去重 | `.copy()` 后必须改 `abbr` |
| 精度一直 0 分，但 predictions 里有正确答案 | 答案抽取函数没抽出来 | 改 `eval_cfg.pred_postprocessor`，再用 `--mode eval --reuse <ts>` 重评估 |
| 性能模式报"不支持" | 用了非流式模型任务 | 换成 `*_stream_*`，或把配置里 `stream=True` |
| 输出 token 数远少于 `max_out_len` | 服务端提前 EOS | `generation_kwargs.ignore_eos=True` |
| 性能数据比预期差很多 | 加了 `--debug` | `--debug` 强制单 worker/单核，压测别开 |
| 性能结果矩阵里长度和配置不符 | `synthetic` 的 string 模式长度是**字符**不是 token；tokenid 模式 decode 有损；chat 接口会加模板 | 用 tokenid 模式，或接受偏差；看 `full.jsonl.actual_input_tokens` 核对 |
| `--max-num-workers 4` 没用 | 加了 `--debug` | 二选一 |
| PrefixCache 报 404 / 找不到页面 | 用的是旧版文档快照 `v3.1-20260415` | 换 `readthedocs.io/zh-cn/latest/` |
| `prepare` 跑了很久 | `O(总 token)`，128K × 几百条 = 几千万 token | 正常；先 `inspect` 确认规模再 `prepare` |
| 理论命中率就是到不了目标 | 每组请求数不够（首条必 miss） | 见 007 §2；加 `requests.count` |
| 实际命中率和理论差很多 | block_size/tokenizer 不一致；未 reset 缓存；顺序不符 | 逐项核对 006 §4 的六条前置 |
| 批量任务跑一半挂了 | — | `--reuse <时间戳>` 续测；`--response-anomaly` 时检测结果也会继承 |

## 3. 三个高频误解

### 3.1 "华为云的工具"

准确说法：**昇腾生态 / AISBench 评测基准委员会**的开源工具（Apache-2.0，GitHub `AISBench/benchmark`）。华为云/昇腾的 MindIE、ModelArts 文档会引用它，但它不是云控制台上的一个功能，也不只能在昇腾上跑（官方有 A100 最佳实践）。

### 3.2 "`ais-bench` 和 `ais_bench` 是两个东西吗"

同一个项目的两种写法：

- 项目名：`AISBench`（曾用 `ais-bench`）
- 主命令行：`ais_bench`（下划线）
- 插件命令行：`ais-bench-prefix-cache`（连字符）
- pip 包：`ais_bench_benchmark`

拼错就是 command not found。

### 3.3 "精度和性能用同一份数据"

不能。区别在 `answer`：

- 精度要 `answer`（参考答案）来算分；
- 性能不需要答案，甚至会把 `answer` 写成占位值。

PrefixCache 的 `requests.jsonl` 里 `answer` 固定是 `"none"` —— **拿去跑精度只会得到 0 分**。反过来，开源数据集可以同时用于两种场景（性能只是不看 answer）。

## 4. 能力边界（别指望它做的事）

| 做不到 | 说明 | 替代 |
|---|---|---|
| 测非 OpenAI 兼容的私有协议 | 只认 HTTP + OpenAI 风格接口 | 自己写 model 后端（`develop_guide/new_model`） |
| PrefixCache 编排多个独立实例 | 只支持单入口单/多 DP | 多实例就多跑几次 |
| PrefixCache 做精度 | `answer="none"` | 用开源/自定义数据集 |
| 压测时精确控制每条请求的发送时刻 | 只有 `request_rate`（1/rate 秒一条）和 RPS 分布 | 要逐条时间戳用 Mooncake Trace 数据集 |
| 跨机器的分布式压测 | 单机客户端 | 多机起多个客户端，或上专业压测平台 |
| 替代 profiling | 只给端到端/请求级指标 | 要看 kernel/算子用 nsys、`vllm bench`、msprof |

## 5. FAQ

**Q：不装 AISBench 本体，能只用 PrefixCache 造数据吗？**
能。`pip3 install -e ./plugins/prefix_cache` 就够 `inspect/prepare/validate/analyze`。`run` 才需要本体。

**Q：`prepare` 需要连推理服务吗？**
不需要。只需要 tokenizer 和语料。可以用它当"离线造数机"。

**Q：为什么 `prepare` 出来的 prompt 有 128K，但我只给了几句 GSM8K？**
因为输入 = 公共前缀 + seed + 语料后缀，128K 的主体是构造出来的公共前缀。见 006 §5。

**Q：`target_hit_rate=0.9` 但 `effective` 只有 0.86？**
目标超出可达区间，被压到边界。加请求数（007 §2）。

**Q：`TARGET_UNREACHABLE` 会让我 CI 失败吗？**
不会，只告警不改退出码。只有配置错/产物损坏/服务不可用才非零退出。

**Q：为什么实际命中率总是比理论低？**
块对齐、调度顺序、缓存淘汰、warmup 不完整都会让实际偏低。5 pp 内属正常，超过就看 `analysis.json` 的 `warnings` 和 `full.jsonl` 的 `watermark_*`。

**Q：能用 SGLang / TensorRT-LLM 吗？**
插件文档只写 vLLM 的 `queries/hits` 指标和 `/reset_prefix_cache`。其他引擎要自己确认指标名和 reset 接口。

**Q：`--num-warmups` 和插件的 warmup 是一回事吗？**
不是两套。插件的按 `Group × DP` 定向预热，在 baseline 之前；`--num-warmups` 是 AISBench 自己的。要 baseline 后只含正式请求，设 `"--num-warmups": 0`。

**Q：AISBench 的结果能直接横比 vLLM benchmark 吗？**
指标定义对齐了（官方声明），但**负载形状**必须一致才有意义。同一个数据集、同样的并发/长度才能比。

## 6. 常用排错命令

```bash
# 配置到底解析成了什么
ais_bench my_config.py --dry-run

# 某任务的配置文件在哪
ais_bench --models xxx --datasets yyy --search

# 看真实输入 token 数（不是配置值）
python - <<'PY'
import json
for line in open("outputs/<run>/result/<run>.full.jsonl"):
    r = json.loads(line)
    print(r["target_input_tokens"], r["actual_input_tokens"],
          r["shared_prefix_tokens"], r["seed_tokens"], r["natural_suffix_tokens"])
    break
PY

# 服务端到底有没有命中
curl -s localhost:8000/metrics | grep -E 'prefix_cache|gpu_cache_usage'
```
