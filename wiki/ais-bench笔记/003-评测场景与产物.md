# 003 评测场景与产物

> 一句话：AISBench 的**场景**由 `--mode` 决定，**任务**由「模型 × 数据集 × 汇总器」的笛卡尔积决定，**产物**按 `mode` 落到不同子目录。
> 版本基线：`v3.1-20261013-master`。

## 1. `--mode` 八种取值

【文档】

| mode | 含义 | 典型用途 |
|---|---|---|
| `all`（默认） | 推理 + 评估 + 汇总 | 正常精度评测 |
| `infer` | 只推理 | 先拿到 predictions，评估慢慢调 |
| `eval` | 只评估 | 改了 `pred_postprocessor` 后**重评估**，不重跑推理 |
| `viz` | 只出可视化/汇总 | 从已有结果重出报告 |
| `perf` | 性能压测 | TTFT/TPOT/吞吐 |
| `perf_viz` | 性能结果重算 + 重绘 | 改 `stats_list` 加 P95 分位后重算（配 `--reuse`） |
| `agent` | Agent 评测 | 走 Harbor |
| `agent_viz` | Agent 结果可视化 | — |

参数是**按 mode 生效**的：精度参数只在 `all/infer/eval/viz` 生效，性能参数只在 `perf/perf_viz` 生效，Agent 参数只在 `agent/agent_viz` 生效；公共参数全模式通用。

## 2. 精度测评

### 2.1 两种被测对象

| 类型 | `attr` | 说明 |
|---|---|---|
| 服务化 | `"service"` | 走 HTTP，OpenAI 兼容。vLLM / Triton / MindIE / TGI 都是这条 |
| 本地 | `"local"` | 进程内加载权重（HF / vLLM 离线）。没有 TTFT 这类服务端指标 |

### 2.2 多任务：笛卡尔积

```
子任务数 = len(models) × len(datasets)
```

4 个组合就 4 个子任务，默认**串行**。要并行：

```bash
ais_bench --models A B --datasets X Y --max-num-workers 4
```

`--max-num-workers` 范围 `[1, CPU 核数]`，默认 1；`--debug` 会强制为 1。

### 2.3 精确控制配对：`model_dataset_combinations`

不想要笛卡尔积时，在自定义配置文件里显式声明：

```python
model_dataset_combinations = [
    dict(models=[models[0]], datasets=[datasets[0]]),
    dict(models=[models[1]], datasets=[datasets[1]]),
]
```

⚠️ 唯一标识是 `abbr`。用 `.copy()` 复用配置**必须**改 `abbr`，否则同 `abbr` 的组合被当成重复任务跳过。

### 2.4 中断续测 / 失败重测

```bash
ais_bench <config.py> --reuse 20250628_151326
```

- 中断时中间结果落在 `predictions/<abbr>/tmp_<数据集>/tmp_<pid>_<n>_<ts>.json`。
- `--reuse` 指到时间戳目录，从断点继续；日志会打 `Found N tmp items, run infer task from the last interrupted position`。
- 只重测部分任务：改配置文件只保留要续的任务 + `--reuse`。
- ⚠️ 续测可能改变请求顺序 → 结果有微小波动。
- 开了 `--response-anomaly` 时续测会继承已有检测结果（`completed` 不重检，`skipped/failed/unavailable` 重检）。

### 2.5 合并子数据集

MMLU、C-Eval 这类有子集的数据集，默认拆成多行子任务。要合成一行：

```bash
ais_bench --models vllm_api_general --datasets ceval_gen --merge-ds
```

合并后只出整体分，子集分不再单列；续测也**必须**继续带 `--merge-ds`。

### 2.6 固定请求数

```bash
ais_bench ... --num-prompts 500          # 简单方式，按数据集顺序取前 N 条
```

进阶：配置文件里 `datasets[0]['reader_cfg']['test_range'] = '[10:20]'`，支持起始/步长。两者同时存在时 `--num-prompts` 优先。**不支持随机抽样/打乱顺序**。

### 2.7 多次独立重复推理（avg@k / pass@k / cons@k）

在 `generation_kwargs` 里设 `num_return_sequences=k`：

```python
models[0]["generation_kwargs"] = dict(temperature=0.01, ignore_eos=False, num_return_sequences=5)
```

输出会多出几行：

| metric | 含义 |
|---|---|
| `accuracy (5 runs average)` | 5 次平均 |
| `avg@5` | 同义 |
| `pass@5` | 5 次里至少 1 次对 |
| `cons@5` | 5 次全对（consistency） |

⚠️ 数据集/请求数会**成倍膨胀**，时间和内存都显著上升，开之前先想清楚要不要。

### 2.8 推理结果重评估（不重跑推理）

场景：模型答对了，但答案抽取函数没抽出来，精度 0 分。

1. 改 `eval_cfg` 的 `pred_postprocessor` / `dataset_postprocessor`；
2. 用 `--mode eval --reuse <时间戳>` 重评估。

```bash
ais_bench ais_bench/configs/accuracy_benchmark/inference_re_eval_zh_cn.py --mode eval --reuse 20250628_151326
```

这是**很实用**的一个能力：评估逻辑调参不用重烧 GPU。

### 2.9 预置示例配置

`ais_bench/configs/accuracy_benchmark/` 下有 8 个官方样例，直接抄改：

`single_task_zh_cn.py` / `multi_task_zh_cn.py` / `multi_task_parallel_zh_cn.py` / `multi_task_resume_partial_zh_cn.py` / `ceval_merge_zh_cn.py` / `fixed_prompts_zh_cn.py` / `multi_repeat_zh_cn.py` / `inference_re_eval_zh_cn.py`

## 3. 性能测评

### 3.1 硬约束

【文档】三条前置条件，缺一条就跑不了：

1. 能直连的服务进程；
2. 数据集准备好（开源 / `synthetic_gen` / 自定义 / PrefixCache）；
3. **模型后端必须是流式接口** —— 其他接口不支持。

### 3.2 指标口径

**Performance Parameters**（每条请求的分位统计，`N` 是样本数）：

| 指标 | 含义 |
|---|---|
| `E2EL` | 端到端时延（End-to-End Latency） |
| `TTFT` | 首 token 时延（Time To First Token） |
| `TPOT` | 每输出 token 时间（Time Per Output Token） |
| `ITL` | token 间时延（Inter-Token Latency） |
| `InputTokens` / `OutputTokens` | 输入/输出 token 数 |
| `OutputTokenThroughput` | 单请求级别的输出吞吐 |

统计维度：`Average / Min / Max / Median / P75 / P90 / P99 / N`。`stats_list` 最多同时承载 **8** 个维度。

**Common Metric**（端到端）：

| 指标 | 含义 |
|---|---|
| `Benchmark Duration` | 总时长 |
| `Total / Success / Failed Requests` | 请求数 |
| `Concurrency` / `Max Concurrency` | 实际平均并发 / 峰值并发 |
| `Request Throughput` | QPS |
| `Prefill Token Throughput` | prefill 吞吐 |
| `Input / Output / Total Token Throughput` | token 吞吐 |

指标定义与 [vLLM benchmark](https://github.com/vllm-project/vllm/tree/main/benchmarks) 对齐 → **可以直接横比**。

### 3.3 稳态压测

```bash
ais_bench ... -m perf --pressure --pressure-time 30
```

`--pressure` 开压测模式，`--pressure-time` 单位秒，范围 `[1, 86400]`，默认 15。用于跳过冷启动、拿系统"真实最佳"。详见 `advanced_tutorials/stable_stage`。

### 3.4 投机推理指标

```bash
ais_bench ... -m perf --spec-decode
```

从服务端 Prometheus `/metrics` 拉投机解码相关指标。只在 `perf` 模式有效。

### 3.5 自定义序列长度

把数据集任务换成 `synthetic_gen_string`，改 `synthetic_config` 的 `Input/Output` 分布；再配 `ignore_eos=True` 保证输出打满。见 005 篇。

### 3.6 性能结果重算

改了 `default_perf` 的 `stats_list`（比如加 P95）之后：

```bash
ais_bench --models vllm_api_stream_chat --datasets demo_gsm8k_gen_4_shot_cot_chat_prompt \
          --summarizer default_perf --mode perf_viz --pressure --debug --reuse 20250628_151326
```

必须显式带 `--summarizer default_perf`。会**覆盖**原来的 `*.csv` / `*_details.json` / `*_plot.html`。

### 3.7 单机规格上限

【文档】在 `Intel Xeon Platinum 8480P` 上实测的资源占用：

| 请求数 | Input | Output | 峰值内存 | 磁盘 | 计算耗时 |
|---|---|---|---|---|---|
| 10,000 | 1024 | 1024 | < 16 GB | 0.12 GB | 3 s |
| 10,000 | 1024 | 4096 | < 16 GB | 0.16 GB | 4 s |
| 10,000 | 4096 | 4096 | < 16 GB | 0.17 GB | 6 s |
| 50,000 | 4096 | 4096 | < 32 GB | 0.80 GB | 30 s |
| **250,000** | **4096** | **4096** | **< 64 GB** | **4.00 GB** | **150 s** |

单机上限：`RequestCount × (Input + Output) = 250000 × (4096+4096) ≈ 2.02e9`。资源占用与这个乘积近似成正比。

> 注意：这是**性能数据计算**的占用，不含把 prompt 造出来（PrefixCache 的 `prepare` 是另一笔账，见 007）。

## 4. Agent 测评

【文档】通过 [Harbor](https://github.com/harbor-framework/harbor) 执行，统一语义参数由 `AgentParamAdapter` 转成各家 Agent 的 kwargs/env。

```bash
ais_bench -a terminus-2 --model hosted_vllm/qwen3 --api-base http://0.0.0.0:8080/v1 -n 5
```

关键参数：`-a/--agent`、`--model`、`--api-base`、`-d/--dataset`（`name@version`）、`-p/--agent-dataset-path`、`-n/--n-concurrent`、`-k/--n-attempts`、`-e/--environment`（docker/daytona/e2b/modal）、`--include-task-name`/`--exclude-task-name`（glob）、`--n-tasks`、`--monitor-port`。

已接入：SWE-Bench（含 Pro/mini）、Terminal-Bench 2.0（Harbor）、τ²-Bench、mini-swe-agent / claude-code / terminus-2 等 Agent。

## 5. 产物对照总表

| 场景 | 结果目录 | 关键文件 |
|---|---|---|
| 精度 | `predictions/`、`results/`、`summary/` | `summary_<ts>.{csv,md,txt}`、`<dataset>.json` |
| 性能 | `performances/<abbr>/` | `<dataset>.{csv,json}`、`<dataset>_plot.html` |
| Agent | 见 `agent_benchmark` 文档 | Harbor 输出 |
| PrefixCache | 插件自己的 `outputs/<run_id>_<ts>/result/` | `full.jsonl` / `requests.jsonl` / `manifest.json` / `analysis.json` |
