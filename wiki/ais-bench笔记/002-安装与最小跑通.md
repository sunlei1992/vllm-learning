# 002 安装与最小跑通

> 目标：从零到跑出一条精度命令 + 一条性能命令，并知道结果落在哪。
> 版本基线：`v3.1-20261013-master`。

## 1. 环境要求

【文档】

| 项 | 要求 | 备注 |
|---|---|---|
| Python | **3.10 / 3.11 / 3.12** | 不支持 ≤3.9，也不兼容 ≥3.13。`v3.1-20260415` 的旧文档只写 3.10/3.11 |
| 网络 | 安装期需联网 | 依赖较多 |
| Conda | 推荐 | 避免依赖冲突 |
| 磁盘 | 看数据集 | 数据集自身占空间；PrefixCache 造 128K 数据会到百 MB 量级 |

```bash
conda create --name ais_bench python=3.10 -y
conda activate ais_bench
```

## 2. 三种安装方式

### 2.1 源码安装（首选）

【文档】推荐源码安装 —— 因为要改 `ais_bench/benchmark/configs/` 下的配置文件、要装 `plugins/`，editable 才方便。

```bash
git clone https://github.com/AISBench/benchmark.git
cd benchmark/
pip3 install -e ./ --use-pep517
ais_bench -h          # 打印帮助 = 装好了
```

### 2.2 pip 一键安装（备选）

```bash
pip3 install ais_bench_benchmark            # 基本功能
pip3 install ais_bench_benchmark[full]      # 全量功能
```

包名是 `ais_bench_benchmark`，卸载也是这个名：`pip3 uninstall ais_bench_benchmark`。

> 局限：只能"基于预置配置快速体验"。要自定义配置文件 / 二次开发，还是用源码安装。

### 2.3 Docker 镜像

【文档】`ghcr.io/aisbench/benchmark/aisbench_benchmark`，支持 x86_64 与 aarch64，覆盖 Ubuntu 22.04/24.04、openEuler 22.03/24.03、Python 3.10/3.11/3.12。2026-07-20 起镜像内预装 Docker + Compose（给 Agent 类评测起子容器用）。

> 镜像名以仓库 README 的徽章链接（`/pkgs/container/aisbench_benchmark`）为准，版本 tag 需现场 `docker pull` 试。

### 2.4 可选依赖（按场景装）

```bash
pip3 install -r requirements/api.txt        # 服务化框架（vLLM / Triton）
pip3 install -r requirements/extra.txt      # 服务化附加
pip3 install -r requirements/hf_vl_dependency.txt        # HF 多模态 / vLLM 多模态离线
pip3 install -r requirements/datasets/bfcl_dependencies.txt --no-deps   # BFCL 函数调用
pip3 install -r requirements/datasets/ocrbench_v2.txt    # OCRBench_v2
```

⚠️ BFCL 必须带 `--no-deps`：`bfcl_eval` 会去装 `pathlib`，而 Python 3.5+ 已内置，不跳过会版本冲突。

### 2.5 PrefixCache 插件（独立安装）

```bash
# 只用离线命令（inspect / prepare / validate / analyze）
pip3 install -e ./plugins/prefix_cache

# 要在线压测 run，还得有 AISBench 本体 + 服务化依赖
pip3 install -e ./ --use-pep517
pip3 install -r requirements/api.txt
pip3 install -r requirements/extra.txt
```

命令行入口是 **`ais-bench-prefix-cache`**（连字符），等价形式 `python -m ais_bench_prefix_cache.cli`。

## 3. 跑通第一条精度命令

### 3.1 前置

1. **一个推理服务**：支持 `/v1/chat/completions`。最省事的是 vLLM：
   ```bash
   vllm serve <model> --port 8080
   ```
2. **gsm8k 数据集**：从 <http://opencompass.oss-cn-shanghai.aliyuncs.com/datasets/data/gsm8k.zip> 下载，解压后的 `gsm8k/` 放进 `ais_bench/datasets/`。

### 3.2 改模型配置

```bash
ais_bench --models vllm_api_general_chat \
          --datasets demo_gsm8k_gen_4_shot_cot_chat_prompt --search
```

`--search` 打印出每个任务对应的配置文件**绝对路径**，然后改模型那份：

```python
from ais_bench.benchmark.models import VLLMCustomAPIChat

models = [
    dict(
        attr="service",
        type=VLLMCustomAPIChat,
        abbr='vllm-api-general-chat',
        path="",                  # 词表路径，精度场景一般不用配
        model="",                 # 服务端模型名，空串=自动获取
        stream=False,
        request_rate=0,           # 每 1/request_rate 秒发 1 个请求；<0.1 表示一次性全发
        use_timestamp=False,
        retry=2,
        api_key="",
        host_ip="localhost",
        host_port=8080,
        url="",                   # base url 不是 http://ip:port 时才配，配了会忽略 host_ip/host_port
        max_out_len=512,
        batch_size=1,             # 最大并发
        trust_remote_code=False,
        generation_kwargs=dict(temperature=0.01, ignore_eos=False),
    )
]
```

**不想改文件也可以命令行覆盖**（2026-08 新增）：

```bash
ais_bench --models vllm_api_general_chat --datasets demo_gsm8k_gen_4_shot_cot_chat_prompt \
          --host-ip 127.0.0.1 --host-port 8000
```

### 3.3 执行

```bash
ais_bench --models vllm_api_general_chat --datasets demo_gsm8k_gen_4_shot_cot_chat_prompt
```

### 3.4 结果

```
dataset                 version  metric   mode  vllm_api_general_chat
----------------------- -------- -------- ----- ----------------------
demo_gsm8k              401e4c   accuracy gen                   62.50
```

## 4. 跑通第一条性能命令

**必须加 `-m perf`，且模型任务必须是流式接口**（`stream=True`）：

```bash
ais_bench --models vllm_api_stream_chat \
          --datasets demo_gsm8k_gen_4_shot_cot_chat_prompt -m perf
```

测固定输出长度时，模型配置里的 `generation_kwargs` 要加 `ignore_eos=True`，否则服务端提前 EOS，实际输出 token 数对不上配置值。

输出两张表：`Performance Parameters`（E2EL/TTFT/TPOT/ITL/token 吞吐，含 Average/Min/Max/Median/P75/P90/P99）和 `Common Metric`（时长、成功率、并发、QPS、各类 token 吞吐）。详见 003 篇。

## 5. 跑起来之后看什么

执行时终端有实时刷新看板：

```
Base path of result&log : outputs/default/20250628_151326
Task Progress Table (Updated at: 2025-11-06 10:08:21)
+----------------------------------+-----------+---------------------+-----------+-------------+------...
| Task Name                        |   Process | Progress            | Time Cost | Status      | Log Path ...
| vllm-api-general-chat/demo_gsm8k |    547141 | [####        ] 4/8  | 0:00:11   | inferencing | logs/infer/...
```

- `P` 键暂停/恢复刷新（复制用），方向键翻页，`Ctrl+C` 退出。
- `--debug` 让详细日志直接打屏，**不落盘**。

### 输出目录（精度场景）

```
outputs/default/20250628_151326/
├── configs/           # 三个任务配置合成的一份 py
├── logs/
│   ├── eval/<abbr>/*.out      # 精度计算阶段日志
│   └── infer/<abbr>/*.out     # 推理阶段日志
├── predictions/<abbr>/*.json  # 每条请求的输入/输出/参考答案
├── results/<abbr>/*.json      # 精度计算的原始分数
└── summary/
    ├── summary_<时间戳>.csv
    ├── summary_<时间戳>.md
    └── summary_<时间戳>.txt
```

### 输出目录（性能场景）

```
outputs/default/20251106_103326/
├── configs/
├── logs/performance/*.out
└── performances/<abbr>/
    ├── <dataset>.csv          # 单请求性能明细（对应 Performance Parameters 表）
    ├── <dataset>.json         # 端到端汇总（对应 Common Metric 表）
    └── <dataset>_plot.html    # 并发/时延可视化，Chrome/Edge 打开
```

```bash
pip3 uninstall ais_bench_benchmark
```

## 7. 在本工作区落地时的建议

- 上游仓**不要**放进 git：`tmp/` 已在 `.gitignore` 里，建议 `git clone` 到 `tmp/ais-bench`，或直接放 `~/code/aisbench` 之类的工作区外路径。
- 数据集（几 GB）也不要入库，`ais_bench/datasets/` 是仓库内路径，跟着 clone 走会污染 git status —— 建议改配置文件里的 `path` 指向工作区外。
- 本机是 Mac（无 NPU），能跑的是"客户端 + 远程/本地 CPU vLLM 服务"这条组合；AISBench 本身是纯 Python 客户端，不需要加速卡。
