# 005 测试数据构造

> 一句话：AISBench 有**四条**造数路径。选哪条取决于你要控制什么 —— 长度？分布？公共前缀？缓存命中率？语义真实性？
> 版本基线：`v3.1-20261013-master`。

## 1. 四条路径总览

| 路径 | 入口 | 你能控制什么 | 主要限制 |
|---|---|---|---|
| **开源数据集** | `--datasets <name>` | 用哪份标准数据、shot 数、cot、prompt 形态 | 长度/前缀全都不能控 |
| **随机合成** | `--datasets synthetic_gen_{string,tokenid}` | 输入/输出长度分布（uniform/gaussian/zipf）、请求数 | 只有性能场景；tokenid 只能给**一个**全局前缀 |
| **自定义数据集** | `--custom-dataset-path` 或配置文件 `datasets` 里加项 | 完全自定义的 question/answer | 要自己写 jsonl/csv；没有理论命中率概念 |
| **PrefixCache 插件** | `ais-bench-prefix-cache prepare` | 变长、多 Prefix Group、**目标命中率**、请求顺序、DP 路由 | 目前只面向 vLLM + `/v1/completions`，且是独立插件 |

## 2. 能力对照矩阵（选型就看这张）

| 能力 | 开源 | 合成(string) | 合成(tokenid) | 自定义 | PrefixCache |
|---|:---:|:---:|:---:|:---:|:---:|
| 输入长度精确到 **token** | ❌ | ❌（字符长度） | ✅ | 手写 | ✅ |
| 输出长度按分布生成 | ❌ | ✅ | ✅ | ✅（`.meta.json`） | ✅ |
| **一个**全局公共前缀 | ❌ | ❌ | ✅ `PrefixLen` | ❌ | ✅ |
| **多个**公共前缀（分组） | ❌ | ❌ | ❌ | ❌ | ✅ 任意组数 |
| **指定缓存命中率** | ❌ | ❌ | ❌ | ❌ | ✅ 全局理论值 |
| 理论 vs 实际命中率对账 | ❌ | ❌ | ❌ | ❌ | ✅ Prometheus 差分 |
| 请求发送顺序可控 | ❌ | ❌ | ❌ | ❌ | ✅ 5 种策略 |
| 语义真实（真人写的问题） | ✅ | ❌ | ❌ | ✅ | 半（后缀是 GSM8K） |
| 能用于**精度**评测 | ✅ | ❌ | ❌ | ✅ | ❌（`answer` 固定 `"none"`） |
| 能用于**性能**评测 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 只用离线环境就能造出来 | — | ❌ | ❌ | ✅ | ✅（`prepare`） |

结论：**只要涉及"公共前缀"或"命中率"，只有 PrefixCache 能干**（详见 006/007 篇）。其余三条按"要不要真实语义""要不要分布"二选一。

## 3. 开源数据集

### 3.1 位置与目录

默认在 `ais_bench/datasets/`，程序按配置自动检索。

```
ais_bench/benchmark/configs/datasets/
├── gsm8k/
│   ├── gsm8k_gen.py
│   ├── gsm8k_gen_0_shot_cot_str.py
│   ├── gsm8k_gen_4_shot_cot_str.py
│   ├── gsm8k_gen_4_shot_cot_chat_prompt.py
│   ├── gsm8k_gen_0_shot_cot_str_perf.py
│   └── README.md
├── aime2024/  mmlu/  gpqa/  ...
```

### 3.2 命名规则（看懂就不用每次翻文档）

```
{数据集}_{评测方式}_{shot数}_shot_{逻辑链}_{请求类型}_{任务类别}.py
```

以 `gsm8k_gen_4_shot_cot_chat_prompt.py` 为例：

- `gsm8k` —— 数据集
- `gen` —— 评测方式（目前只支持生成式）
- `4_shot` —— 4 条示例
- `cot` —— 带逻辑链提示；不写则无
- `chat_prompt` —— 请求类型为对话；`str` 为纯字符串
- 任务类别缺省 = 精度；`_perf` = 性能模板

指定时可省略 `.py`。

### 3.3 覆盖面

| 类别 | 代表数据集 |
|---|---|
| 通用语言理解 | ARC_c/e、SuperGLUE_BoolQ、MMLU、MMLU_Pro、CMMLU、C-Eval、FewCLUE 系列 |
| 数学推理 | GSM8K、AIME2024/2025、MATH、MGSM、dapo-math-17k |
| 代码 | HumanEval、HumanEvalX、MBPP、LiveCodeBench、IFEval |
| 长文本 | LongBench、LongBenchV2、NeedleBench_v2、LCSTS、XSum、LAMBADA、DROP |
| 多模态 | MMMU/MMMU-Pro、TextVQA、DocVQA、InfoVQA、Video-MME、VideoBench、VocalSound、OCRBench_v2、OmniDocBench、MMStar |
| 多轮对话 | ShareGPT、MT-Bench |
| 能力专项 | BFCL（函数调用）、GPQA、BBH、HellaSwag、PIQA、SIQA、Winogrande、TriviaQA |

### 3.4 数据集任务配置长什么样

```python
gsm8k_datasets = [
    dict(
        abbr='gsm8k',                        # 唯一标识
        type=GSM8KDataset,                   # 数据集类，不要改
        path='ais_bench/datasets/gsm8k',     # 相对路径以源码根为基准，也可绝对路径
        reader_cfg=gsm8k_reader_cfg,
        infer_cfg=gsm8k_infer_cfg,
        eval_cfg=gsm8k_eval_cfg,
    )
]
```

`eval_cfg` 里的 `pred_postprocessor` 就是答案抽取函数 —— 精度为 0 时先改它，再用 `--mode eval --reuse` 重评估（见 003 §2.8）。

## 4. 随机合成数据集

> 【文档】**仅支持性能评测场景**，不支持精度。

两种模板，改 `ais_bench/benchmark/configs/datasets/synthetic/` 下的 `synthetic_config`：

### 4.1 `synthetic_gen_string.py` —— 随机字符串

```python
synthetic_config = {
    "Type": "string",
    "RequestCount": 1000,
    "StringConfig": {
        "Input":  {"Method": "uniform", "Params": {"MinValue": 50, "MaxValue": 500}},
        "Output": {"Method": "uniform", "Params": {"MinValue": 20, "MaxValue": 200}},
    }
}
```

| 分布 | 参数 |
|---|---|
| `uniform` | `MinValue` / `MaxValue`（`[1, 1048576]`，可相等=定长） |
| `gaussian` | `Mean` / `Var` / `MinValue` / `MaxValue` |
| `zipf` | `Alpha`（`(1.0, 10.0]`，越大越均匀）/ `MinValue` / `MaxValue`（必须 > Min） |

### 4.2 `synthetic_gen_tokenid.py` —— 随机 token id

```python
synthetic_config = {
    "Type": "tokenid",
    "RequestCount": 5000,
    "TokenIdConfig": {
        "RequestSize": 512,   # 单请求 token 数
        "PrefixLen": 256      # 所有请求前面 256 个 token 相同
    }
}
```

**这就是"最朴素的公共前缀压测"**：一条全局前缀，长度固定。想做 24 组不同前缀 + 90% 命中率，它做不到 → 用 PrefixCache。

### 4.3 两个已知偏差（文档明说）

1. **`string` 模式的"长度"是字符数，不是 token 数** → 矩阵里的长度会和配置值不符。
2. **`tokenid` 模式**：随机 token 要 decode 成字符串再发给服务，词表映射多对一/一对多 → token 数也会波动。
3. `chat` 类接口会额外拼字符串 → 长度再偏一点。

### 4.4 输出长度打不满？

`generation_kwargs` 里设 `ignore_eos = True`。

## 5. 自定义数据集

> 【文档】"仅供临时性的、非正式的数据集使用"。支持 `mcq` 和 `qa` 两类任务，都只支持 `gen` 推理。

### 5.1 格式

`qa` 类型（问答）：

```jsonl
{"question": "752+361+181+933+235+986=", "answer": "3448"}
```

`mcq` 类型（选择）：`question` + 连续大写字母选项 + `answer`：

```jsonl
{"question": "165+833+650+615=", "A": "2258", "B": "2263", "C": "2281", "answer": "B"}
```

也支持 `.csv`（首行表头）。

### 5.2 命令行

```bash
ais_bench --models vllm_api_general \
          --custom-dataset-path xxx/test_qa.jsonl \
          --custom-dataset-data-type qa \
          --custom-dataset-infer-method gen --mode all
```

| 参数 | 说明 |
|---|---|
| `--custom-dataset-path` | jsonl/csv 路径；一旦用了 `--datasets` 本参数失效 |
| `--custom-dataset-meta-path` | `.meta.json` 路径 |
| `--custom-dataset-data-type` | `mcq` / `qa`，不填则自动判断（能解析出 A/B/C 选项就当 mcq） |
| `--custom-dataset-infer-method` | 目前只支持 `gen` |

配置文件方式（仅精度）：往 `datasets` 里加

```python
datasets = [
    ...,  # 普通数据集
    {"path": "xxx/test_qa.jsonl", "data_type": "qa", "infer_method": "gen"},
]
```

### 5.3 逐条指定输出长度：`max_tokens`

```jsonl
{"question": "...", "answer": "...", "max_tokens": 1024}
```

csv 就加一列。**注意：文档说该字段目前不适用于性能压测场景**。

### 5.4 `.meta.json`（仅性能场景）

不写也行，程序会自己解析。需要**采样**或**输出长度分布**时才要：

| 字段 | 取值 | 说明 |
|---|---|---|
| `request_count` | int/str | 生成多少条；不足循环填充，超出截断 |
| `sampling_mode` | `shuffle` / `random` / `default` | 采样模式 |
| `output_config.method` | `uniform` / `percentage` | 输出长度分布类型 |
| `output_config.params.min_value/max_value` | int | uniform 用 |
| `output_config.params.percentage_distribute` | `[[长度, 占比], ...]` | percentage 用 |

```json
{
  "output_config": {"method": "percentage",
                    "params": {"percentage_distribute": [[100, 0.5], [200, 0.3], [400, 0.2]]}},
  "request_count": "10",
  "sampling_mode": "shuffle"
}
```

### 5.5 自定义多模态数据集

`--datasets mm_custom_gen`（改配置里的路径和 prompt），jsonl 每行：

```json
{"type": "image", "path": ["/data/a.jpg"], "question": "what is the brand?", "answer": "dakota"}
```

`type` ∈ `image` / `video` / `audio`；`path` 可以是数组（多图/多视频）。仅性能场景（`answer` 实际未使用）。

## 6. PrefixCache：指定命中率

只列"它和上面三条的根本区别"，细节见 006 篇：

- 数据 = **公共前缀（每组独立 canonical） + 全局唯一 seed + 自然文本后缀**；
- 可以指定**全局理论命中率**（如 90%），插件反解出该多长的前缀并离线算出可达区间；
- 可以指定 **Prefix Group 数量**（如 24 组）和分配方式（uniform / zipf / weights）；
- `prepare` 纯离线，产物 `requests.jsonl` 可以直接拿去喂别的压测工具；
- `run` 会自己用 Prometheus 差分算**实际命中率**，和理论值对账。

## 7. 选型决策树

```
要测精度？
├─ 是 ──> 有标准数据集吗？
│         ├─ 有 ──> 开源数据集（--datasets）
│         └─ 没有 ──> 自定义数据集（--custom-dataset-path）
└─ 否（性能）
   ├─ 想控输入/输出长度分布？ ──> synthetic_gen_string / custom + .meta.json
   ├─ 只想要一个固定公共前缀？ ──> synthetic_gen_tokenid (PrefixLen)
   ├─ 要多个前缀组 + 指定命中率 + 理论/实际对账？
   │        └─> PrefixCache 插件（唯一解）
   └─ 只是想复现真实业务输入形式 ──> 自定义数据集 / 从线上日志转 jsonl
```
