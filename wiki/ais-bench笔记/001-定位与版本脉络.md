# 001 定位与版本脉络

> 结论先行：**AISBench 不是华为云控制台上的一个产品功能**，而是昇腾生态里一个 Apache-2.0 的开源评测工具。华为云/昇腾的 MindIE、ModelArts 相关文档引用它，但工具本身在 GitHub 上独立维护，也能纯 GPU/NVIDIA 环境跑。
> 资料截至 2026-10-28。

## 1. 一句话是什么

【文档】AISBench Benchmark 是**基于 [OpenCompass](https://github.com/open-compass/opencompass) 构建的模型评测工具**，兼容 OpenCompass 的配置体系、数据集结构与模型后端实现，并在此基础上扩展了对**服务化模型**的支持。

支持两大类推理任务的评测场景：

| 场景 | 覆盖 | 关键点 |
|---|---|---|
| 🔍 **精度测评** | 服务化模型 + 本地模型，覆盖文本/多模态/多语言 | 复用 OpenCompass 的数据集与评估器 |
| 🚀 **性能测评** | 只为**服务化模型**提供，延迟 / 吞吐 / 并发压测 | 指标打点对齐 vLLM benchmark |

还有第三类：**Agent 测评**（`--mode agent`），通过 Harbor 框架跑 SWE-Bench、Terminal-Bench 2.0、τ²-Bench 等（2026.4 起陆续接入）。

## 2. 不是什么（避免预期错位）

| 误解 | 事实 |
|---|---|
| "华为云自研的云服务" | 独立开源项目，GitHub `AISBench/benchmark`，Apache-2.0；也可在 NVIDIA A100 上跑（官方有 A100 最佳实践） |
| "只能跑昇腾" | 本地推理后端支持 HuggingFace / vLLM 离线；服务化只要 OpenAI 兼容接口就行 |
| "就是个精度打榜工具" | 一半价值在**服务化性能压测**（TTFT/TPOT/ITL/QPS）和**可复现的数据构造** |
| "等于 OpenCompass" | 是它的扩展分支；数据集/评估器大量复用，但任务编排、服务化后端、性能链路是重写的 |
| "等于 vLLM benchmark" | 只对齐了**指标口径**，不是同一个工具；AISBench 还能测精度和多后端 |

## 3. 血脉：从昇腾工具集里长出来的

```
昇腾 msit 工具集 (msit/components/benchmark)
   └─> gitee.com/ascend/ais-bench        # 早期独立仓，现在访问 403
        └─> GitHub AISBench/benchmark    # 2025-12-19 架构全面重构后成为主仓
             ├─> PyPI: ais_bench_benchmark            (2026-06-15)
             └─> GHCR: aisbench_benchmark 镜像 x86/ARM (2026-06-15)
```

- 旧的 `gitee.com/ascend/ais-bench` 现在打不开（403），**不要再照旧链接找代码**。
- 名字演变：`ais-bench`（旧）→ `AISBench`（新）。命令行入口仍是 `ais_bench`（下划线），但 PrefixCache 插件是 `ais-bench-prefix-cache`（连字符），两个都在，别混。
- 归属主体：**AISBench 人工智能系统性能评测基准委员会**（文档页脚署名）。

## 6. 和邻居们怎么分工

| 工具 | 强项 | 什么时候用它而不是 AISBench |
|---|---|---|
| **OpenCompass** | 数据集最全、学术打榜、社区最大 | 只要精度榜、不需要服务化性能和压测数据构造 |
| **vLLM benchmark**（`vllm bench serve`） | 轻量、和 vLLM 同源、指标定义权威 | 只想快速看一眼 serving 性能，不需要多后端/精度/造数 |
| **EvalScope**（阿里） | 中文生态、ModelScope 集成好 | 主战场在 ModelScope / 需要它的可视化平台 |
| **MindIE 自带测试工具** | 昇腾原生、和 MindIE 深度绑定 | 只测 MindIE、要厂商口径 |
| **AISBench** | 精度+性能+造数一体；OpenAI 兼容多后端；APC 命中率可控可复现；昇腾侧事实标准 | 需要**可复现的压测数据**（尤其前缀缓存命中率）、或要同时出精度和性能报告 |

一句话选型：**"我要造一批特定形状/特定缓存命中率的请求去打服务" → AISBench 是目前最省事的**。

## 7. 在昇腾生态里的位置

- MindIE 3.x 文档的精度测试章节直接写"以 AISBench 工具为例"：<https://www.hiascend.com/document/detail/zh/mindie/300/index/index.html>
- 昇腾社区的 KVCache、推理优化文章里，性能数据基本都用 AISBench 出。
- 但注意：**AISBench ≠ 昇腾专属**。它和硬件解耦，后端就是 HTTP 接口；在 A100 上跑是官方支持的路径（`best_practices/practice_nvidia`）。
